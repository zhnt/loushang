# 第13章 安全、隐私与数据管理

> 文档版本：V1.0.0

说明凭证、工作目录、会话数据、扩展信任和高影响操作的安全要求。

本章以用户可执行操作为主，命令和路径均应在目标安装环境中再次核对。

## 13.1 最小权限原则

每次任务只开放完成目标所需的模型、目录、工具和外部访问范围。

### 功能要点
- 只读分析默认不需要 edit、write 和 bash。
- 写入阶段可以按步骤临时扩大工具范围。
- 操作系统权限、沙箱和组织审批应与工具策略共同工作。

### 操作步骤
1. 列出任务必需能力。
2. 以最小 --tools 集合启动。
3. 遇到明确缺口后再增加工具。
4. 高影响阶段结束后收回权限。

### 命令或配置示例
```text
loushang --tools read,ls,find,grep -p "只读审查。"
/tools off bash
```

### 验证方法
- 任务能完成且未使用无关能力。
- 拒绝路径不会通过替代工具绕过。

### 注意事项
- Loushang 工具列表不等于完整系统权限边界。
- 扩展可能贡献新能力，必须一起审查。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“最小权限原则”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。

## 13.2 凭证保护

模型 API Key 和其他凭证应由环境或秘密管理系统注入，不应写入项目与会话。

### 功能要点
- Coding 层不管理 OAuth 生命周期。
- 日志、trace、命令历史和导出都可能意外包含秘密。
- 凭证应按最小范围、最短寿命和可轮换原则管理。

### 操作步骤
1. 从可信秘密存储获取凭证。
2. 只注入当前进程所需变量。
3. 避免 echo、调试转储和提交。
4. 任务结束后清理并按策略轮换。

### 命令或配置示例
```text
export PROVIDER_API_KEY=<redacted>
unset PROVIDER_API_KEY
```

### 验证方法
- 版本控制和会话中找不到真实凭证。
- 泄露检测和轮换流程可用。

### 注意事项
- 示例中的占位符不能替换成真实 Key 后提交。
- 共享终端和 CI 日志需要额外脱敏。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“凭证保护”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。

## 13.3 工作目录安全

工作目录决定可见文件和工具相对路径，应在执行前后持续核对。

### 功能要点
- 不要把主目录、根目录或包含多项目的宽泛目录作为写入范围。
- 符号链接和挂载点可能把操作带出表面目录。
- 恢复会话时真实工作树可能已变化。

### 操作步骤
1. 确认绝对路径和项目根。
2. 检查 Git 状态与符号链接。
3. 为高风险任务使用隔离分支或工作树。
4. 完成后核对所有变更路径。

### 命令或配置示例
```text
pwd
git status --short
git diff --name-only
```

### 验证方法
- 所有修改都位于授权项目范围。
- 用户既有修改没有被覆盖或丢失。

### 注意事项
- 不要对未解析变量或通配符执行破坏性命令。
- 参考仓库默认只读，除非任务明确授权修改。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“工作目录安全”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。

## 13.4 会话与日志保护

会话、工作日志、诊断和导出可能包含源代码、提示、路径、模型用量和工具结果。

### 功能要点
- 数据分类应与项目源代码至少同等级处理。
- 共享前需要内容审查和最小化。
- 保留期限应满足恢复、审计和隐私要求。

### 操作步骤
1. 识别所有会话与导出存储路径。
2. 设置适当文件权限。
3. 共享前删除无关敏感内容。
4. 到期后使用可审计流程清理。

### 命令或配置示例
```text
loushang --list-sessions
loushang --export review.html
loushang --diag-export --diag-output diag.json
```

### 验证方法
- 只有授权用户能够读取归档。
- 删除和保留行为符合组织规则。

### 注意事项
- 不要把私有会话上传到公开问题或公共存储。
- 删除前确认是否受审计或法律保留要求约束。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“会话与日志保护”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。

## 13.5 扩展与依赖信任

扩展、插件和包可能执行 Python 代码或贡献工具，应视为供应链组件管理。

### 功能要点
- 来源、版本、完整性和权限声明需要可追溯。
- 更新可能扩大工具或网络能力。
- Manifest 提供说明，但不能替代代码审查。

### 操作步骤
1. 只从可信来源获取资产。
2. 审查代码、依赖和权限变化。
3. 在隔离项目运行离线测试。
4. 固定版本并记录升级结论。

### 命令或配置示例
```text
loushang --list-plugins --list-plugins-format json
loushang --list-packages --list-packages-format json
/extensions
```

### 验证方法
- 每个执行资产都有已知来源和版本。
- 禁用后贡献不会继续进入新会话。

### 注意事项
- 不要自动更新未经验证的生产扩展。
- 依赖安装脚本可能产生网络和文件系统副作用。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“扩展与依赖信任”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。

## 13.6 高影响操作

删除、覆盖、重置、推送、发布、付费调用和外部消息等操作需要更高确认等级。

### 功能要点
- 模型提出动作不构成用户授权。
- 目标、范围、影响和恢复方式必须在执行前明确。
- 能使用可恢复方式时应优先使用。

### 操作步骤
1. 展示将执行的完整目标和命令。
2. 获取当前用户明确确认。
3. 执行前保存状态或建立检查点。
4. 执行后报告结果和恢复可能性。

### 命令或配置示例
```text
git status --short
git diff --stat
loushang --export pre-action.html
```

### 验证方法
- 动作只影响确认范围。
- 失败或部分完成状态被准确报告。

### 注意事项
- 不要用含糊的继续或随便作为高影响授权。
- 不能保证恢复时必须在执行前明确告知。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“高影响操作”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。

## 13.7 模型数据边界

发送给模型的提示、文件片段和工具结果可能离开本地环境，应遵守所选提供方和组织的数据政策。

### 功能要点
- 不同端点可能具有不同地域、保留和训练政策。
- 模型路由变化也可能改变数据处理边界。
- 最小上下文可以降低不必要的数据暴露。

### 操作步骤
1. 确认提供方和完整端点。
2. 分类将发送的数据。
3. 删除无关秘密和个人信息。
4. 记录必要的授权与处理依据。

### 命令或配置示例
```text
loushang --list-models --list-models-format json
loushang --source-info
```

### 验证方法
- 实际端点符合组织允许列表。
- 请求只包含完成任务所需上下文。

### 注意事项
- 不要仅凭模型显示名称判断数据去向。
- 代理和兼容端点需要单独审查运营主体。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“模型数据边界”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。
