# 第7章 工具使用与治理

> 文档版本：V1.0.0

说明内置工具、工具选择、最小权限、调用呈现和扩展拦截。

本章以用户可执行操作为主，命令和路径均应在目标安装环境中再次核对。

## 7.1 内置工具概览

新的交互会话默认提供 read、ls、find、grep、bash、edit 和 write 等内置工具。

### 功能要点
- ls、find、grep 和 read 优先用于文件探索与读取。
- bash 适合管道、重定向、构建、测试和 Git 操作。
- edit 与 write 会修改文件，应在目标和范围明确后启用。

### 操作步骤
1. 使用 /tools 查看当前工具集合。
2. 按任务只保留必要工具。
3. 先读取再修改，修改后立即查看差异。
4. 把关键工具结果写入交付说明。

### 命令或配置示例
```text
/tools
/tools only read,ls,find,grep
/tools reset
```

### 验证方法
- 工具列表与本轮任务需要一致。
- 工具事件能够显示名称、参数、状态和结果摘要。

### 注意事项
- 默认工具集合可能受启动参数或扩展影响。
- 工具存在不代表每次调用都应自动批准。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“内置工具概览”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。

## 7.2 命令行工具选择

--tools、--tool、--no-tools 和 --no-builtin-tools 提供不同粒度的工具配置入口。

### 功能要点
- --tools 接受工具名称集合，用于收窄活动工具。
- --no-tools 禁用工具能力，只允许模型使用已提供上下文。
- --no-builtin-tools 可保留其他贡献来源而关闭内置工具。

### 操作步骤
1. 列出任务需要的读、写和执行能力。
2. 用 --tools 显式设置最小集合。
3. 运行提示并观察工具是否足够。
4. 仅在明确缺少能力时增加工具。

### 命令或配置示例
```text
loushang --tools read,ls,find,grep -p "只读分析。"
loushang --no-tools -p "只根据输入回答。"
loushang --no-builtin-tools -p "使用扩展能力。"
```

### 验证方法
- 模型看不到未启用的工具。
- 任务完成时没有发生范围外副作用。

### 注意事项
- 工具名称必须来自当前会话实际发现结果。
- 关闭内置工具不等于关闭所有扩展工具。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“命令行工具选择”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。

## 7.3 会话内工具控制

/tools 命令允许在交互会话中查看、关闭、收窄和恢复工具集合。

### 功能要点
- 工具变更只应影响预期会话上下文。
- off 用于停用指定工具，only 用于保留白名单。
- reset 恢复会话的默认工具解析结果。

### 操作步骤
1. 运行 /tools 记录当前状态。
2. 对高风险阶段关闭 bash、edit 或 write。
3. 用 only 建立只读阶段。
4. 需要写入时再恢复精确工具。

### 命令或配置示例
```text
/tools off bash
/tools only read,ls,find,grep
/tools reset
```

### 验证方法
- 命令结果清楚显示启用和禁用项。
- 后续模型调用使用更新后的工具定义。

### 注意事项
- 切换工具后应重新说明本阶段目标。
- 不要把工具关闭当作文件系统沙箱的替代。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“会话内工具控制”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。

## 7.4 只读探索

只读探索阶段用于形成可靠上下文，避免模型在不了解项目时直接修改文件。

### 功能要点
- 目录枚举用于理解边界，检索用于定位相关实现。
- 读取应从入口、配置、测试和目标模块开始。
- 结果摘要应区分已读事实和待验证推断。

### 操作步骤
1. 用 ls 或 find 获取文件结构。
2. 用 grep 搜索符号、参数和错误消息。
3. 用 read 查看最相关的连续上下文。
4. 形成修改假设和验证计划。

### 命令或配置示例
```text
loushang --tools ls,find,grep,read -p "定位会话恢复实现。"
loushang --tools read,grep -p "解释配置优先级。"
```

### 验证方法
- 结论引用了实际文件和符号。
- 分析阶段工作树保持不变。

### 注意事项
- 不要一次读取大量无关生成文件。
- 搜索结果需要通过上下文阅读确认含义。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“只读探索”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。

## 7.5 Shell 工具

bash 工具提供灵活的命令执行能力，同时也是最需要约束和审查的内置工具之一。

### 功能要点
- 构建、测试、格式化、Git 查询和文本管道适合使用 bash。
- 命令应明确工作目录、目标和预期副作用。
- 破坏性命令、网络发布和权限提升需要额外确认。

### 操作步骤
1. 先请求只读或验证性命令。
2. 检查命令中是否含宽泛通配符、重定向或递归删除。
3. 执行后记录状态码和关键输出。
4. 失败时先诊断，不要盲目重复高影响命令。

### 命令或配置示例
```text
git status --short
git diff --check
python -m pytest tests/path/to/test_file.py
```

### 验证方法
- 命令在预期目录执行并返回可解释状态。
- 输出足以证明验证范围和结果。

### 注意事项
- 不要执行未解析目标的删除、重置或覆盖命令。
- 命令输出可能泄露环境变量和本地路径。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“Shell 工具”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。

## 7.6 文件修改工具

edit 适合对现有文件做精确变更，write 适合创建或整体写入明确目标文件。

### 功能要点
- 修改前必须读取目标上下文并保留用户已有变化。
- 小范围补丁更易审查、回滚和验证。
- 生成文件应与源文件和构建流程区分。

### 操作步骤
1. 检查 Git 状态和目标文件内容。
2. 选择 edit 或 write 并限制路径。
3. 修改后运行格式检查和相关测试。
4. 查看 diff 确认没有意外重写。

### 命令或配置示例
```text
git status --short
git diff --stat
git diff --check
```

### 验证方法
- 差异规模与任务目标一致。
- 用户的无关改动和未跟踪文件没有被覆盖。

### 注意事项
- 不要修改只读参考仓库或任务范围外文件。
- 自动格式化可能造成大面积机械差异，应单独审查。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“文件修改工具”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。

## 7.7 工具事件与审计

工具事件记录名称、输入、状态和结果，可在终端转录、会话、诊断或导出中呈现。

### 功能要点
- --render-tool-events 可在适用模式下显示工具事件。
- 工具结果应做必要截断，避免转录被巨量输出占满。
- 审计关注授权、输入、结果和后续决策，而非只看命令名称。

### 操作步骤
1. 启用工具事件渲染。
2. 执行一个可预测的只读工具调用。
3. 检查开始、结束和失败状态。
4. 导出会话并确认事件顺序。

### 命令或配置示例
```text
loushang --render-tool-events -p "读取 README 并总结。"
loushang --export tool-session.html
```

### 验证方法
- 每次调用都有可关联的开始与结束状态。
- 失败不会被最终答复描述为成功。

### 注意事项
- 工具结果可能包含源代码、路径和秘密。
- 审计导出前应执行敏感信息检查。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“工具事件与审计”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。

## 7.8 扩展工具拦截

扩展可以在工具调用前后执行检查、阻止高风险动作或调整结果呈现。

### 功能要点
- ToolCallDecision 可在调用前阻止或解释拒绝原因。
- ToolResultDecision 可在调用后规范结果。
- 扩展守卫是额外治理层，不替代操作系统和组织策略。

### 操作步骤
1. 审查扩展源码和 manifest 权限声明。
2. 用离线示例验证允许与阻止路径。
3. 在真实项目中先应用于低风险工具。
4. 记录拦截原因和用户可采取的下一步。

### 命令或配置示例
```text
python examples/coding/extensions/04_tool_guard.py
python examples/coding/extensions/11_online_tool_guard.py
```

### 验证方法
- 被禁止的调用不会产生实际副作用。
- 允许调用仍能正常返回并进入会话记录。

### 注意事项
- 来源不明的守卫扩展本身可能造成风险。
- 结果修改不能掩盖真实失败或伪造验证证据。

### 记录建议
- 建议在会话名称、工作日志或交付说明中记录“扩展工具拦截”的实际选择。
- 如实际结果与预期不同，应保留命令、状态码和最小复现信息。
