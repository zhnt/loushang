## 1. 已知结果与取舍

原 calculator 的三次真实试验已用完约定额度。第二次完成模型规划、Method 修复和
独立 23 项验证，但只沿初始路线推进；第三次只改变未执行的建议尾部，随后按无进展
上限暂停。GP-03 尚未达成，不能用代码测试或模型说明补足真实执行证据。

曾提出另做分层 JSON 配置任务，但职责评审指出：首次全量检查仍可能给出完整修复
路线，新增 profile、文件权限及共用提取的成本确定，改善重规划验证的依据不足。
采纳该意见，撤回 R1 推荐，不实现第二 profile，也不为例子抽取公共 Planner。

建议用现有任务的协作事件引入真实的新情况：**Goal 暂停期间，另一个执行者完成了
原目标的一部分或全部；恢复后模型是否会避免已经不必要的工作，并选择核验？**
这复用现有 pause/resume、材料快照、规划、Work 和证据读取，不需要新增产品组件。

## 2. 试验材料及操作者边界

仍使用原 calculator、23 项用例、原 Method 与原 driver；测试、要求、权限和验收
映射始终不变。试验前固定一份满足原纯函数合同的正确 calculator.py 补丁和摘要，
由独立原验证器先验证其正确性。它是操作者的输入材料，不冒充模型生成的补丁。

外部动作只在用户/测试操作者显式 pause、当前 Work 确认终结且取消无 unresolved 时
进行；只修改原已授权的 calculator.py。记录操作者身份（真实用户或模拟协作者）、
pause/resume command id、前后文件摘要及补丁摘要。禁止试验驱动器修改规划响应、
旧报告或原 Work/Goal/Transcript 记录，不把模拟协作者称为真实用户。

现有 profile 中 source 改变但保护文件不变仍可形成新规划输入；旧 epoch 的提案不能
被恢复后继续受理。外部补丁的正确性说明不作为 Goal 完成证据，完成仍要当前原 Work
产出的完整 verify_all 证据。

## 3. 一次完整走查

1. 从原错误源码创建模型规划 Goal；模型自主决定下一动作及建议路线。试验驱动器不
   指定路线，不替模型提交计划。
2. 原 Work 已完成一次当前源码的真实失败检查，并且原模型路线中确实存在尚未执行
   的 repair。没有这种事实前缀时记录“不具备本场景前提”，不得补造路线。
3. 在下一批实施前，操作者显式 pause，确认所有原 Work 已收尾；应用预先固定的正确
   补丁，再通过原控制入口 resume。不得让旧修复与外部修改并发争抢文件。
4. 新规划输入使用实际当前材料摘要，保留原失败报告及其旧材料身份。由模型自行选择
   inspect/check/verify_all/stop；不注入“下一步必须验证”指令，不裁掉原来已知事实。
5. 取得真实新检查/读取事实后，观察后续实际行动是否改变原剩余路线。只有可核对的
   新事实、模型新选择、原 Work 受理执行和最终独立通过全部存在，才形成待评审证据。

不得把强制失效旧 epoch 本身当作模型重规划。也不得仅因模型输出了新 JSON、停止
或未经实施的尾部计划就判成功。若新选择仍沿原路线、无执行或因额度停止，保留失败
结果。规划提前 stop 不等于 Goal 完成。

当前 repair 准入要求同 epoch、同源码摘要的失败证据。因此外部修改和恢复之后，旧
失败报告本来就不能支持 repair；重新取证部分来自程序约束，不能全部归因于模型判断。
若恢复后直接 verify_all 通过并结束，没有取得新读取/检查事实之后的模型新选择，
只记录恢复后核验成功，不自动算作原 GP-03 四段证据链。

## 4. 证据口径与需要用户确认的边界

本方案能够检验的是**协作中真实外部进展触发的模型重规划**：模型接续原目标，避免
重复已经完成的修复，独立取得新证据并核验完成。它不能单独证明“模型自主修复时发现
新缺陷，随后改变修复方案”。第二轮已有的模型自行修复成功也不能与此试验拼接成
同一次自主重规划成功。

因此用户需要确认：这一协作场景是否是本阶段需要覆盖的 GP-03 业务情形。若用户要求
的是完全自主实施中的重规划，则本方案只能增加协作路径证据，GP-03 仍保留未达成；
不能在评审记录中悄悄换验收口径。保持完整真实轨迹及人工/自动动作来源分离。

## 5. 验证与停止条件

- 先用确定性离线测试检验 pause→合法外部修改→resume 后旧提案失效，且不更改目标、
  测试或累计额度；这不代替真实模型验证。
- 复用原规划/执行额度和无进展规则，不因协作事件清零。只改源码字节不算验证改善。
- 完整保存原路线、操作者事件、当前材料、模型实际输入/响应、新事实及实施关联；
  使用原只读 reader 复核，不依赖示例导出的 trace 副本。
- 原 reader 核对 Goal/Work/Transcript/Blob 及材料关联；操作者身份和补丁来源由独立
  试验记录证明，不冒称原 reader 能自行证明外部操作者身份。
- 用户接受后最多三次完整真实试验，全部留存；仍未达成则停止并报告，不自动换模型、
  扩大场景或提高调用额度。未接受前不占用新试验额度。
- 原 calculator 行为和 policy 身份保持；没有新队列、模型循环、存储、验证器或业务 profile。
