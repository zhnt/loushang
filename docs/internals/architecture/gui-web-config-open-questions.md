## 问题起因

Web 改造中加入了 token 登录页，导致本机打开 `127.0.0.1:1422` 也需要手动输入 token。这不符合当前需求，也暴露出配置归属、客户端与 Host 边界、未来账户认证尚未理清的问题。

## 当前明确的需求

- Web 默认监听 `127.0.0.1`，只供本机访问；用户可以在配置文件中修改监听 IP。
- 当前不需要连接认证，应直接连接。账户和认证能力后续统一设计，不提前要求 token 或强制 HTTPS。
- GUI、TUI、Web 应访问同一套 Host 能力与共享数据，不能各自形成一套业务配置。
- 语言、外观、Markdown 主题等显示偏好可以各端独立保存。
- 必须支持纯浏览器访问远程 Loushang：访问者本机什么都没安装，也没有 `~/.loushang`。

## 必须覆盖的使用场景

| 场景 | 配置与存储需要考虑的边界 |
| --- | --- |
| 本机安装前端和 Host | 本机 `~/.loushang` 中需要清楚区分客户端配置与 Host 数据 |
| 只安装 GUI/TUI，连接远程 Host | 本机连接记录与远程业务配置分别归属哪一端 |
| 只安装 Host，作为服务器 | 服务端独立运行，向其他桌面或浏览器提供能力 |
| 本机什么都没安装，只访问远程 Web | 不依赖访问者本机目录；通过 API 使用远程 Host 的配置和数据 |

## 对现有设计的影响

浏览器不能像桌面程序一样直接读写访问者电脑的 `~/.loushang`。但网页可以通过 API 请求 Host 读写文件，因此文件配置机制本身仍可使用；需要重新明确文件属于哪台机器、哪个用户，以及谁有权访问。

不能把“Host 机器的用户级目录”等同于“所有访问者的账户配置”。一旦远程 Host 被多个账户使用，当前单用户目录与共享状态就需要明确的隔离边界。

现有模型配置、提供商凭据、连接记录、置顶和访问记录等，也需要重新核对各自的归属，不能仅根据当前文件放在哪里决定。
