## Complete Responsibility And Reuse

A79 replaces the complete selected snapshot to live revision handle, builtin or
external-data validation, host distribution lock, PublishedPluginPackage,
PluginSourceBinding, InstalledPlugin, resolution construction and failure cleanup
program. The same slice replaces installed member capture, exact manifest check,
METADATA/RECORD and deterministic ZIP generation. Public callers use the original
Coding entries. No Definition, Provider, approval or Graph execution moves here.

Package Product owns its internal `_selected_plugin_revisions` program. It uses
actual selected snapshot DTOs and currentness readers, original Plugin revision
errors, package/binding/plugin DTOs and PluginRuntimeResolution. The filesystem
VerifiedRevisionHandle remains the original FD owner; it cannot directly replace
an immutable in-memory capture whose every read checks a live Product selection.
The new internal handle retains the original capture contract without adding a
second FD, lease, registry, state manager or transaction.

Existing ExactProductSourceFiles remains the installed filesystem owner. Its
nine original publication/inspection methods are unchanged by AST. They already
shared native IO and are not credited again. The minimum extension owns the
previously missing installed-member reader and Wheel byte writer, using the
original Path/stat/read/ZIP implementations. InstalledPythonDistributionEvidenceResolver
remains the sole distribution evidence resolver. Its original implementation and
all other1959 existing production sources are byte-identical.

Coding keeps actual Artifact/spec classes and fields, closed member lists,
Product IDs/version/trust/reserved declarations, source selection, budgets,
metadata and Generator bytes, public signatures and thin compatibility entries.
Its20-field immutable revision policy supplies values, pure lookups and actual
owner constructors. The six-field Wheel recipe supplies source location and
wire/metadata policy. Neither is an IO callback interface. Core performs all
resolve/read/ZIP/resolver operations at their original positions. Capability
locations are module-file plus relative-component data, never a Code source_root
callback. The distribution factory only constructs the existing resolver.

The Wheel builder resolves relative to package_builtin_wheel.__file__; selection
validation and host grants resolve relative to plugin_dependency_grants.__file__.
Both remain lazy and separate. These two original source identities are not
unified or cached. Root resolution is Path(module_file).resolve().parent, relative
components and resolve(strict=True), with no new admission or filesystem checks.

A79 is distinct from the rejected or deferred A35–A37/A51 managed-composition and
A53 ordinary-Worker proposals. Catalog initial/handoff/refresh, Session Graph and
previous cleanup owners already exist and are directly reused. This batch does
not wrap those Code programs in new callbacks or count their prior mechanisms.

## Original Ordering And Failure Contracts

- Handle construction verifies the selected manifest, then builds its diagnostic
  root and pinned file/directory tables. It does not read that root or add live
  currentness at construction. Each read checks currentness before path parsing.
- acquire first verifies and constructs another real Code handle, verifying its
  manifest again. Closed state is independent; already-open BytesIO streams
  survive handle close. The private Code class/FQN and public return surface stay.
- The narrow verify/open_file runtime arity remains. Inherited newer FD/probe
  operations are not made functional for this snapshot handle. The Callable
  aliases express the existing override without Any, ignores or API expansion.
- Base validation short-circuits before expected Wheel generation; base data-only
  declarations are checked after the hash. Capability path resolution remains
  inside its original OR expression, before later trust/reservation/hash checks.
  External declarations are verified before Product/trust policy checks.
- The host lock repeats the original capability map lookup before its try, then
  constructs the real resolver before resolving the source root. Only the
  original InstalledPythonDistributionEvidenceError is translated; source-root
  OSError, interruption and other errors retain their original propagation.
- Handle construction remains outside the inner cleanup try. packages.append
  precedes InstalledPlugin construction. An InstalledPlugin failure can close
  the same current handle in both inner cleanup and forward prefix cleanup.
  A close failure replaces the active error and stops the remaining prefix.
  This is not rewritten with a generic cleanup aggregator.
- Member reads retain regular/hardlink acceptance, symlink/reparse refusal,
  ancestor-loop bounds, before-stat budget, full read_bytes and after-stat
  identity checks. There is no bounded-read or mode/owner/TOCTOU behavior change.
- Wheel entry order, sorted RECORD rows, LF, base64 digests, 1980 timestamps,
  regular0644 Unix attributes, ZIP_STORED and close-error precedence stay exact.
  The byte builder does not publish files.

Private helper method FQNs and private TypeError wording may change. Public
exports/signatures, actual DTO own annotations, pickle paths, error graphs and
full produced Wheel bytes are preserved in the bounded observations.

actual code for responsibility/reuse, runtime/failure and data/compatibility.

were independently checked. No bounded actual-code blocker remains. The runtime
probe preserves only its48 executed cases; the33 values observer functions and
classes retain their original AST. Root accepts only this complete input-custody

graph freshness and the nine documentation/link invariants pass. The changed-path
plan selects Coding/Harness/Hosting and native platform routes, with AI/Agent
unselected; this is a plan, not a claim that broad or native routes were executed.

prove a real Store selection transaction, installed-host metadata, native Windows

Session publication. Member tests use real POSIX files; synchronous raised
CancelledError does not prove asynchronous cleanup. Existing adjacent consumers
retain their own narrower evidence. These limits do not waive remaining Goal
compatibility, recovery or cross-entry obligations.
