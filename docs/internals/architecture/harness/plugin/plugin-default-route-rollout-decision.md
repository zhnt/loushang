# Plugin Default Route Rollout Decision

Status: partial Linux fresh-workspace decision, 2026-10-01. This is a rollout
decision, separate from the Plugin owner's acceptance of the architecture
candidate and from each Product admission decision. It does not close PLC9.

## Decision

The Product owner accepted automatic first-B entry for genuinely fresh Linux
Coding workspaces. Ordinary Session startup uses the no-write preflight and
offline Product cutover; an existing B fence reopens through the Product owner.
Unfenced old Plugin inputs refuse before writes. The implementation has focused
Product and Runtime proof; the complete Coding regression remains a release
gate. Windows ordinary first-B entry remains closed until native admission.

Keep the general third-party Worker route closed. Do not infer Plugin use from an
author artifact, valid declaration, controlled Source, installed Wheel, or
selected revision. Keep Worker candidate admission and native tests behind
their explicit Product flags and per-install decisions. Do not treat the
Theme candidate or any future Method, Asset, Source, or dependency profile as
part of a universal default route.

The Product may continue to expose each already admitted Resource through its
own explicit consumer. A data Skill needs a selected new-Session Resource and
Model Input use; a Prompt needs its Command/Resource consumer; a Theme needs
the selected Screen setting and visible style consumer. Their individual
evidence does not decide the Worker route.

## Reopen Criteria

Before Windows Arch can be admitted as a production Session consumer, the
Product owner must prepare its Installation and Session private-data roots
under the current B fence with native owner-only ACLs and pinned directory
identity. The Arch Session, backup, restore, and deletion owners must bind the
same Installation key and current root; a changed ACL, reparse point, replaced
ancestor, or stale Product selection must refuse before writing or deleting.
Native Windows evidence must include fresh creation, cross-process reopen,
tamper refusal, and interruption recovery. The new ACL chain and root receipts
cover Session preparation and Installation identity only; Linux-only
backup/deletion receipts do not meet the remaining owner gate.

Reconsider the route only after one Product-selected revision and its exact
native closure are bound to a current opt-in, receipt, Session, Capability
publication, and ordered cleanup on each admitted platform. Require retained
Linux and Windows native results, restart and reboot recovery, stale/changed
Source and policy negatives, GC retention, kill-switch and rollback evidence,
and a frozen full regression. A separate Product owner decision must name the
scope, platform, requiredness, and rollback switch. The ordinary route remains
unchanged until that decision is recorded and verified.

This decision can be revised without pretending that the current candidate
artifacts were already usable by an ordinary Product Session.
