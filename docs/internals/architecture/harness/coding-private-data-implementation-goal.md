## Goal 描述

在保持现有用户能力、存量数据和运行合同的前提下，完成 Coding 插件私有数据的备份、核验、独立确认删除、恢复、恢复结果确认及备份过期的职责归一。以高内聚、低耦合为约束，直接复用 Harness 已有的管理、确认、Journal、树与文件操作、原生平台适配及资源寿命能力，删除 Coding 中被这些组件覆盖的重复实现；只有明确证明既有组件及其配置无法满足原合同，才最小扩充原 owner。Coding 最终仅保留 Arch 产品政策、内容与布局/兼容声明、必要的产品决定及薄入口，不保留第二套存储、树处理、日志读写、清理或事务引擎。按用户扩围及数量确认，以整个Coding归属源码净减少至少8,000行为完成线，争取减少约9,000–10,000行，同时要求受影响生产源码总量净减少及重复机制数量下降。每个切片必须交付完整可用场景、实际复用证据、旧实现删除、兼容验证和三视角代码评审，禁止用目录搬迁、扩大通用框架或牺牲既有能力完成指标。

## 必须满足的架构约束

1. **高内聚。** 同一机制的规则、事实投影和寿命由原职责 owner 负责；产品决定留 Coding，通用机制回到原 Harness 组件。确认、执行、记录仍按 R3 分工，不因迁移合并不同事实权威。
2. **低耦合。** 叶子操作只接收确切身份、已准入窄端口、值与必要政策输入；不传递可任意访问依赖的大 Session/Product/context，不读取其它 owner 私有字段。Harness 不反向依赖 Coding，不把 AppService、Work、Method 或 UI 塞进此底座。
3. **复用先于扩充。** 顺序固定为：直接调用原组件→已有 Profile/配置/端口组合→原 owner 的最小扩充。新增通用 manager、registry、存储系统、动作引擎或一整套回调框架不属于本 Goal 的解法。
4. **迁入必须复用。** 每项拟迁入 Harness 的实现先写“现有能力→不能满足的确切差异→复用/扩充点→删除旧体”对照。不能仅因代码产品中性就原样移动；原算法确需提取时，原消费者与私有数据消费者必须共同使用该一份算法，平台边界保留在原 native adapter。
5. **删除与接管同时完成。** 切片结束时旧操作体已删除；公开路径可薄转发到唯一实现。新旧双引擎、逐层 facade 包装、复制状态机或常驻回退开关不能作为完成状态。
6. **兼容优先于机械统一。** 保持 R3 的原目录、锁、哈希域、字段/ID、错误与优先级、平台发布/根代际、部分状态、确认与恢复合同。原 POSIX 只读路径、两平台 status、Windows candidate 各沿原准入与逐动作锁模式；不新增锁或降低/提高原准入来适配共享模板。
7. **实现按子系统归位。** 用户明确要求精简过程中不把共享实现放入 Harness 根目录。优先复用 Journal、Transcript、Session、Resources、Plugin Management、Worker 等各原子系统 owner；必要扩充也放回对应子系统，不新增根目录工具堆或跨领域的杂项包。模块输入保持窄值/窄端口，原依赖方向与高内聚、低耦合约束同时成立。

## 验收证据与执行约束

- **先冻结旧行为。** 在提取相关实现前，从基线固定旧格式字节、ID/hash、异常类别/code/适用行序及原调用结果；不使用新构造器生成预期。原生身份/ACL 另用真实临时对象与原写入路径验证，不伪造持久授权。
- **复用对应测试。** 按 R3 EV-01–EV-07 复用已有 backup/deletion/restore/expiry/Journal/CLI/SDK/平台证据；仅为确有缺口增加必要案例。不重复付费模型实验、不新建测试矩阵或 PR gate，不要求无关全套测试。
- **不改变原读取/错误合同。** 特别核查 status 无新增静止期拒绝、Windows 原 transaction 复用、JSON 同字节解析的单行/跨行/schema/tail/phase 原优先级。
- **验证净收益。** 每个切片列源码路径、基线/结果行数、Coding 删除/新增、Harness/其它层删除/新增、全系统净变、原重复算法与当前唯一调用者。Python 物理行含空行/注释；不压行、不藏入生成器/数据脚本、不把搬到其它产品目录的实现算作删除。
- **评审实际代码。** 实现后从职责/复用、运行/失败、数据/兼容三个视角评审；文档通过不能代替代码和行为验证，阻断项关闭后才认定相应切片交付。平台未验证部分明确保留原 candidate/未验证标识。
- **完整切片回退。** 共享实现、调用者、错误/值适配和兼容导出一同回退，切换前结清原动作；不要求用户清空状态或新建 workspace。
- **遵守本机测试方式。** pytest 及调用 pytest 的 make 目标从首轮在 sandbox 外运行，命令局部设置 `LOUSHANG_RUNTIME_DIR=/home/dev/lsspace/.runtime/loushang-tests`；使用主项目 `.venv` 从 worktree 运行 wrapper 前设置该 worktree 的绝对 `PYTHONPATH=.../src`。保留 non-live 等原选择，不影响正常 Product 路径。
- **交付范围单独记录。** 本 Goal 不自行增加远程发布、CI 门禁或平台开放；commit/push/PR/merge 依已有授权与工作区规则执行，不制造额外批准或用户接受记录。
