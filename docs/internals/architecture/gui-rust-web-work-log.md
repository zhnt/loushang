# GUI Rust Web 监听迁移工作记录

日期：2026-11-11。目标：GUI Rust 拥有 HTTP 监听、静态资源、Web 服务生命周期；Coding 保留 Host 请求与执行适配，不再监听 HTTP。

- 读取 ub-mode 和仓库规范，检查 main、GUI 集成分支与工作树状态，避免覆盖其他任务。
- 建立 `feature/gui-rust-web` 专用工作树；确认最新桌面连接目录已由 Rust 管理。
- 选择 GUI 下独立 Rust Web crate：浏览器服务无需初始化 Tauri 窗口或依赖桌面进程生命周期。桌面复用该 crate 的启动入口。
- 先添加本机免认证与来源校验测试；初次离线执行因缺少 HTTP 服务端依赖 `httpdate` 未进入测试，补齐依赖后再观察行为失败。
- 红测试确认本机无凭据访问被拒绝，随后实现 Rust 请求来源策略并通过；真实进程测试覆盖静态资源、来源拒绝、大小限制、Host 状态持久化与重启。
- 移除 Coding 的 `web_server.py`、`web_endpoint.py` 和不再使用的 HTTP 转发/启动逻辑；保留 `web_gateway` 作为私有 stdio Host 适配器。
- Vite 改用 Rust 服务的 HTTP 代理；桌面客户端复用 GUI Rust 启动代码；独立程序的 Web 入口从 Host 包移到 GUI 包。
- Rust 原生检查、118 项前端测试、7 项 Coding 适配测试通过。重复代码检查未发现阈值 0.8 以上候选。
- 复杂度检查定位启动和监听函数，按资源解析、发布、监听和启动等待职责拆分；安装缺失的 Rust 覆盖率工具，避免以复杂度代替 CRAP。
- 首轮浏览器验收发现启动助手进程组继承和 `state` 默认组写权限问题。通过隔离目录和 Host 准入调用栈定位原因；改为独立进程组与新目录 0700，加入针对性回归，而不是绕过准入规则。
- 最终真实 Chromium 验收通过：Vite 和独立 Rust Web 均渲染真实应用并读取同一个运行中的 Host；测试 Host 与 Web 已正常关闭。
- 最终验证：GUI `check:full`、118 项前端测试、2 项桌面路由测试、7 项 Coding 适配测试；Rust Web 的策略、配置、CLI 和真实进程测试通过。Ruff、Rust Clippy、文档和架构依赖检查通过。
- ub-mode：新增 Rust Web 函数的实测覆盖率 CRAP 均低于 10；来源策略 14 个变异全部被杀死；阈值 0.8 的结构重复检查无候选。生成的覆盖率和指标报告不提交。
- 同步 portable、deb 和独立 GUI 包的二进制/静态资源路径；完整安装包未重新制作，不能以源码和运行验收代替安装验收。

## 验收范围与剩余边界

实现者按委托职责接受本机 Web 的归属迁移：GUI Rust 负责监听、资源、HTTP 边界和生命周期；Coding 仅保留 Host 请求/执行适配。保留现有文件位置和会话数据，不增加认证、远程部署层或过渡监听器。未新增 CI gate、平台矩阵或必需检查。
- 最后补齐发现地址的纯本机 URL 校验（禁止凭据、路径、查询和 fragment），保持旧入口的数据边界；对应单元与变异测试执行后记录结果。
- 发现地址校验的 9 个变异全部被杀死；连同来源校验，所选关键边界共 23 个变异无存活。其余函数不冒称完成全量变异。
