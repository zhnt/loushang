### 适用范围与后续事项

本次实质变化由测试失败触发；真实运行只提交了一次通过评审。**评审拒绝→再次规划→
修复**由确定性假模型的真实 SDK 离线测试证明，不能写成本次 Kimi 实测路径。
同样，单任务成功不意味着通用自然语言任务、跨进程续跑、AppHost/AppService 或
任意规模计划已经实现。旧 calculator 和旧 #125 试验结论保持不变。

本轮暴露明显性能限制：Work 日志约 159 MiB，宿主反复重建历史时出现数分钟推进
间隔，进程持续消耗 CPU；未观察到可支持“模型额度耗尽”或“队列超时”的事实。
`RepositoryDomain._verification` 当前为每次验证读取全部 Work 历史，再按 run 投影；
这是静态定位的候选热点，尚未用 profiler 独立量化各环节成本；
后续先测量并比较原按 operation/run 查询的结果与成本，再考虑最小优化。
不应另建日志或索引，也不能通过增大超时掩盖读取成本。本轮冻结运行未热修。

在线输出的 `last_error` 会保留先前验证失败信息，即使后续 advance 已 completed；
它不是当前完成依据。报告以原 Work 状态、当前验证、评审及冷读为准，诊断展示可另行收敛。

精确试验切点保留了模型新增测试中的 7 个未使用导入。这些不是固定 RC 的失败，
未据此制造重规划。随后宿主单独清理这些导入并更新文档；该整理不冒称模型产出，
也不把后续变化的工作树冒充原 `current` 快照。历史完成绑定上述源码切点。
