## 可直接交给执行 agent 的 Goal 描述

在楼上已经交付的本地 Coding SDK Goal 闭环上，增加模型自主规划能力，使系统能够
围绕用户给定的目标、要求、约束和验收依据，由模型提出下一批实施工作，经系统核验
受理后，通过原有 Work、Session、Agent 和工具执行，再依据实际结果重新判断下一步，
直至目标有充分证据证明完成，或因需要用户决定、无法继续、达到限制而明确停止。

模型应真正参与实施路线的选择：根据当前要求、已有工作、检查结果和失败证据，
说明下一批要解决什么问题、为何选择该行动、涉及哪些要求、采用什么 Method（如有）
以及预期获得哪些证据。获得新事实后，模型可以保留、细化或修订后续计划，并留下
可追溯的理由。首版采用逐批规划，允许保留整体路线摘要；不要求一次生成永不改变的
完整任务树，也不能仅让模型复述代码预先固定的步骤便宣称实现自主规划。

模型提出的是候选计划。系统受理前须核验其结构、要求关联、可用能力、所选 Method
的必要约束，以及本轮能够实际保证的权限和资源边界。不能机械判定的内容要明确
标为待核验或需要用户决定。模型不能自行改写目标、扩大授权、放宽测试或改变验收
标准；计划获准也不替代原工具执行时的权限检查。

沿用已接受的职责分工：Goal 保存目标和完成依据；模型提出实施计划；Method 规定
所选工作的契约；Skill 提供局部专业指导；Work 执行并记录实际结果。通用控制和记录
仍归 harnesswork.goal，模型规划由 Coding Product 通过现有下一工作策略合同接入。
显式 Method 方式和模型规划方式共用 Goal 控制、Work 执行及证据验收能力。模型可以
在本轮明确允许的工作选择中决策，但必须遵守用户已经指定的方法和约束；自动发现
或生成任意 Method、Skill 不作为首版前提。

完成裁决继续由领域验收和实际证据共同支持。模型说“完成”、计划全部打勾、Work
成功或某份材料可读，都不足以完成 Goal。最终必须满足当前版本的要求，证据必须
对应实际受测的代码、测试和执行结果。失败、证据过期或缺项时，明确继续、等待或
停止的原因，不能无界重试，也不能把规划重试藏在既有批次限制之外。

本轮先交付一个本地 SDK、单活动目标、调用方显式推进的真实 Coding 场景。沿原
执行路径进行真实模型规划与代码修改，并提供可查询的规划、受理、执行和验收轨迹。
先完成增量专项设计，与已有架构协同，经过三视角评审并关闭阻断项，将重要架构
工作件交用户评审后再实施。本描述生成不等于架构接受或实施授权。

## 当前基础与本轮增量

已有首版由固定 CalculatorPolicy 在验证与 Method 修复之间选择下一批；真实模型
参与代码修复，但不拥有实施路线选择。GoalController、记录组件、三个注入合同、
原 Work 执行与证据消费已经存在，不在本阶段重新建设。

| 已有基础 | 本轮需设计并验证的增量 |
| --- | --- |
| NextWorkPolicy.prepare / confirm_candidate | 模型规划输入、候选结果解析和受理判据；优先沿现有合同适配，确需扩展时说明原因和兼容影响 |
| Goal 要求版本、epoch、批次与 operation 关联 | 规划依据、计划修订、受理/拒绝原因与实际执行的最小关联；明确未受理候选如何追溯 |
| 原 Session / Agent / 模型与工具路径 | 规划调用的执行归属、输入材料、允许动作、取消及用量事实来源；规划失败也必须可观察 |
| 领域验收和持久证据 | 模型计划中的预期证据与实际验收要求相衔接，不把模型期望变成新的验收权威 |
| 既有控制及批次约束 | 对规划调用、候选拒绝重试、实施批次和无进展情况给出有限推进规则 |

以上是候选需求增量，不是声称现有接口必然足够，也不预先要求增加新的公共组件。

## 首个真实场景与成功证据

选择一个小型、可重复还原、具有独立验收条件的 Coding 任务。实施前固定初始项目、
允许修改范围、要求、测试、可用工作种类、Method/Skill 使用边界、模型配置和推进
上限。可以复用现有计算器夹具，但只有它能证明真实路线选择与调整时才作为主验收
场景；否则选择更合适的小任务，避免为了沿用夹具而放宽成功定义。

1. 用户只给出目标、约束和验收依据，不预先指定完整实施步骤；系统保留要求版本。
2. 模型读取允许的当前材料，提出候选实施计划及下一批工作，留下选择理由和预期证据。
3. 系统记录受理结论；不合格候选不能进入实施。合格候选通过已有执行路径产生实际结果。
4. 新检查或执行结果提供新的事实；模型据此重新判断，至少在一条真实轨迹中作出有
   实质影响的计划调整，并说明所依据的事实。仅改写措辞或按原固定流程走到下一步不算。
5. 后续工作完成后，独立验收核对当前要求、受测版本与证据，满足时提交 Goal 完成决定。
6. 关闭后可冷读目标、已受理计划修订、执行关联和完成依据；读取历史不触发规划或重放。

不得通过强迫模型先生成错误补丁、执行中改动约定测试或伪造检查结果制造“重规划”。
真实场景可利用检查后获得的新事实证明调整；异常候选和故障分支用确定性测试验证。
固定模型回复适用于合同测试，不能替代上述真实模型轨迹。

## 必须满足的验收条件

| ID | 完成判据 |
| --- | --- |
| GP-01 自主选择 | 真实模型根据目标与事实提出下一批工作；轨迹能区分模型选择与系统硬约束，不能由固定领域分支预先决定全部实施路线 |
| GP-02 计划受理 | 受理前核验候选结构、当前要求版本、允许能力、方法约束和已声明的限制；结构无效、越界或基于旧版本的候选不得派发，保留可解释的拒绝或等待原因 |
| GP-03 动态调整 | 新证据能影响后续计划，至少一条真实轨迹展示有实质影响的修订；已受理历史保持可追溯，不原地修改活动 WorkRunSpec |
| GP-04 方法与技能协作 | 用户指定的 Method 约束在规划方式下仍适用；Skill 指导不替代 Method、权限或验收。原显式 Method 方式继续可用；不强制每项工作都创建 Method 或使用 Skill |
| GP-05 执行与事实关联 | 规划调用、候选受理与实施工作可追溯到原执行事实；operation→run 仍由 HarnessWork 解析，不复制运行日志或新建原始 token 账本 |
| GP-06 有限推进 | 规划失败、候选连续拒绝、重复无进展和批次耗尽均有有限处理；上限在实施前明确，规划/重试不绕过限制。软提示、调用上限与实际费用硬保证分别表述 |
| GP-07 用户控制与未知结果 | 规划等待或实施期间的暂停、要求修订和取消沿原控制路径处理；过期规划不能随后派发。中断或效果未知时停止新的实施，不盲重试已有操作 |
| GP-08 独立完成 | 完成依据对应当前要求及实际受测版本；模型自报、旧证据、缺项或仅 Work completed 均不能完成 Goal；至少一条真实轨迹最终通过约定验收 |
| GP-09 可查询与冷读 | 可查询当前阶段、候选处理结果、已受理修订、实施结果及停止/完成理由；冷读不调用模型、不执行工作。会话尚未物化、日志不完整或控制恢复不支持时如实呈现 |
| GP-10 交付与兼容 | 真实 SDK/模型轨迹、关键离线反例、三视角评审和实现复核可追溯；对变更涉及的原 Method、Work、输入和控制路径做相称验证，不以全量矩阵替代场景验收 |

## 专项设计必须回答的问题

- 系统环境和组件交互有哪些变化？规划策略如何复用现有三合同，哪些责任仍留在
  Coding，是否确有共享合同增量；若需调整架构，给出影响和评审结论。
- 规划调用如何进入原执行路径并记录事实？读取什么材料、可调用什么工具、如何
  区分规划与实施、如何取消，以及要求变化后的迟到结果由谁拒绝？
- 哪些候选判据由程序强制核验，哪些依赖模型或用户判断？候选输出无效、引用不存在、
  约束无法满足或预期证据不足时，如何处理且避免无限修复输出格式？
- 计划修订与 Goal 要求版本、epoch、Method 身份、原 operation 如何关联？未受理
  候选和失败规划如何复用现有记录留证；不提前扩展为通用计划树或独立事件平台。
- 如何核算规划调用和实施批次的有限额度、判定无进展、呈现停止理由？用量关联
  只补场景所需；没有可靠支撑时不得宣称严格 token 或金额上限。
- 首次规划前后分别已持久保存什么？如何冷读，如何处理尚未物化的 Session？明确
  可恢复控制的范围，不从“Goal 历史可读”推导“任意中断点可自动续跑”。

专项按职责与复用、运行与失败、数据与兼容三个视角评审，固定评审对象修订并记录
阻断项处置。系统环境图、组件关系、关键交互及重要决策仍须用户评审；本轮没有
完成这些评审，不将本需求草案标为已接受设计。

## 范围与收敛原则

首版只覆盖本地 SDK、单活动目标、逐批规划与调用方显式推进。用户可以在现有
控制入口暂停或修订要求；“自主”指模型在授权范围内选择和调整路线，不指无人
值守后台运行或自行获取更多权限。

多目标并行、跨会话迁移、跨进程自动续跑、远程 Goal API、后台调度、任意子代理
任务树、自动生成 Method/Skill、通用语义证明器和完整预算平台不属于完成范围。
复用既有输入队列、Agent loop、WorkRuntime、授权、取消、Journal 和 Blob；只有
真实场景暴露且专项确认的必要缺口才作为底座增量，不借此重启大范围基础设施建设。
